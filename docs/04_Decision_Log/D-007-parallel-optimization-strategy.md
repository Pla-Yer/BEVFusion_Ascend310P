## D-007: 并行化优化策略选择

### Date
2026-03-20

### Background

为了进一步提高pipeline性能，通过高度并行化是极好的工作方向。BEVFusion模型的设计使得雷达分支与图像分支在fusion前都可以独立进行。需要决定采用哪种并行化策略来优化整体性能。

### Options Considered

| Option | Description | Pros | Cons |
|--------|-------------|------|------|
| A. 仅预处理并行 | 点云加载与图像加载并行；体素化与depth_map计算并行 | 实现简单；改动小 | 模型推理仍串行；优化上限有限 |
| B. 仅模型推理并行 | LiDAR分支与Camera分支并行推理 | 显著降低推理时间 | 预处理仍串行；整体优化不完整 |
| C. 预处理+推理并行 | 预处理并行化 + 模型推理并行化 | 全面优化；效果显著 | 实现复杂；需要协调多个并行任务 |
| D. 全流程流水线 | 预处理+推理并行 + 双缓冲 + 流水线 | 最大化并行度；隐藏延迟 | 实现最复杂；需要精细的生命周期管理 |

### Choice
**Option D: 全流程流水线优化**

### Reason
1. **最大化并行度**：预处理内部并行、模型推理并行、预处理与推理流水线并行
2. **隐藏延迟**：通过双缓冲和流水线，有效隐藏预处理延迟
3. **资源利用率高**：CPU和NPU同时工作，最大化硬件利用率
4. **性能提升显著**：从串行到全流程流水线，性能提升巨大

### Risk
- 实现复杂度高，需要精细的生命周期管理
- 双缓冲需要额外的内存开销
- 流水线同步可能引入新的瓶颈

### Mitigation
- 设计清晰的双缓冲机制
- 实现完善的预取线程管理
- 通过profiling持续监控和优化

### Outcome
**已成功实施，效果显著：**

**优化路径：**
1. **预处理并行化**：
   - 图像加载：串行296ms → 并行32ms（提升89%）
   - 深度投影：164ms → 24ms（提升85%）
   - 总流程：792ms → 355ms

2. **模型推理并行化**：
   - 三OM架构实现LiDAR与Camera分支并行
   - NPU推理：185ms → 135ms
   - 总流程：355ms → 270ms

3. **流水线优化**：
   - 双缓冲机制：预分配两个host slot
   - 预取线程：下一帧预处理与当前帧推理并行
   - 总流程：270ms → 166ms
   - FPS：3.7 → 6.01

**最终性能：**
- 总流程时间：2334ms → 166ms（**提升92.9%**）
- 有效吞吐量：0.43 samples/s → 6.01 samples/s（**提升14倍**）
